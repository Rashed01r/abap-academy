# Academy architecture

## Declarative guided curriculum and Data runtime (2026-11-04)

`guided-types.ts` defines bilingual lesson metadata, grouped reference source, artifact relationships, scenario decisions, progressive hints and a final knowledge check. Independent data/development/cloud-project definition files feed `registerGuided` in `guided-curriculum.ts`; curriculum.ts remains the single playable registry. `validateGuided` checks bilingual fields, artifact endpoints, distinct decisions/options, answers and hints; the existing validator also checks source coverage and reference solutions. This is the reusable generation/registration pipeline for complete guided lessons, not a placeholder generator.

Guided missions explicitly contain `challenges: []` and one stable `<mission>-assessment` required activity. They reuse version 2 allChallengesPassed/completeMission and existing once-only XP. ConnectedLesson renders reference-only VisualCodeAnatomy, GuidedExplorer and GuidedAssessment in the existing tabs. A referenceOnly anatomy document never calls parse/simulate, offers no Watch Execution control and shows no invented runtime state. Scenario grading compares every structured answer; checking all decisions correctly plus the knowledge check gates completion. Matching remains optional preparation. Example sources are independent fixtures, not a shared SAP activation sequence.

DictionaryDesigner, SqlFoundationLab and ObjectExplorer are dynamically imported when their active visual tab is first visited. Their state and guided choices/hints/selected artifacts use the bounded existing topic-session cache; achievement records still use the unchanged persistent store. Only the selected lesson mounts; visited tabs preserve state. The curriculum metadata itself still ships in the registry bundle; per-lesson remote/lazy content loading is future work. No dependency, external account, backend or SAP connection was added.

Data missions retain executable SyntaxLab/Monaco/LearningWorkspace. Typed READ and indexed mutations/SORT extend the existing parser, static type checks, bounded interpreter and behavior grader. Immutable lookup/mutation trace metadata powers LookupSummary, TableChangeSummary and existing TableMemory, shared with anatomy. The Knowledge Tree, counter-zoom, Pointer Events resizing, layout preference key and code-draft keys remain unchanged. Planned Dictionary/SQL depth remains visible as previews after their introductory mission is added.

## Visual Code Anatomy authoring contract

`code-anatomy.ts` defines typed groups (stable ID, bilingual title/explanation, source range, optional details/glossary/syntax references, visualizer target and field exploration) and validates source coverage, ordering, localization and matching questions. `anatomy-content.ts` supplies reviewed group definitions for every registered mission and both orientation examples. `anatomy-concepts.ts` is an original beginner glossary with meaning, usage, example, mistake and technical detail. Rendering is shared in `visual-code-anatomy.tsx`; no mission-specific interface is duplicated.

For each new lesson, author meaningful line ranges and matching prompts against the complete example. Cover every nonblank line without overlap. Add a fixed `sourceFingerprint` only after reviewing code, ranges and explanations; do not blindly regenerate it after an example changes. The fingerprint catches source drift, including whitespace that shifts source ranges. `validate:curriculum` rejects missing anatomy or references. Selection uses explicit ranges, not substring lookup. The optional legacy keyword view retains its existing interactions.

The default layout shows complete grouped code, a short explanation and an appropriate result. Type groups show a blueprint, explicitly without a record. Snapshot groups use actual simulator events belonging to that source range; untaken branches show that they were not reached. Repeated groups label the last executed visit, with Watch Execution exposing the existing full trace and controls. Structure assignment highlights both fields from actual changed-field events.

Watch Execution passes an educational range into a separate Monaco decoration collection (dashed purple gutter/underline). Green execution pointers continue to follow trace events only. Clicking source lines selects groups by line number without running code or moving the execution timeline. Editing source clears educational highlighting until the original example is restored. Monaco remains dynamically loaded.

Lab completion accepts correct group matching or the existing optional keyword questions. Selecting groups alone is not assessment. Existing completed labs remain completed, and no progress shape, stable mission ID or XP rule changed in this batch. Syntax Labs remain optional for mission access and mission assessment.
